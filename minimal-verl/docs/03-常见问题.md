## 环境类

### Q: `MPS available: False` 怎么办？

**A**: 三种情况，从最常见到最少见：

1. **你在 Linux/OrbStack VM 里** —— MPS 后端不在 Linux 构建，必须在 **macOS 原生**跑
2. **macOS 太老** —— 需要 macOS 12.3+ (Monterey) 才支持 MPS
3. **PyTorch 版本太旧** —— 需要 PyTorch 1.12+

排查：
```bash
python -c "import torch; print(torch.backends.mps.is_available(), torch.backends.mps.is_built())"
```
- `is_available()=True, is_built()=True` ✅ 完美
- `is_built()=False` → wheel 装错了（Linux wheel），重装 macOS 版
- `is_available()=False, is_built()=True` → macOS 太老

### Q: uv sync 装的是 Linux wheel 怎么办？

**A**: 旧的 `.venv/` 留着，uv sync 不会自动清理。手动删：
```bash
rm -rf .venv
uv sync
```

### Q: HF 下载慢 / 失败？

**A**: 设 HF 镜像（国内用户）：
```bash
export HF_ENDPOINT=https://hf-mirror.com
uv run python scripts/00_check_env.py
```

或者用 HF_TOKEN 提高限速：
```bash
export HF_TOKEN=hf_xxxxxxxx
```

## 数据类

### Q: 怎么换自己的数据？

**A**: 编辑 `data/make_data.py` 里的 `TRAIN_DATA` 和 `TEST_DATA`：
```python
TRAIN_DATA = [
    {"user": "你的评论 1", "assistant": "正面"},
    {"user": "你的评论 2", "assistant": "负面"},
    # ...
]
```

**注意**：
- `assistant` 必须是 `{"正面", "负面", "中性"}` 之一（跟 reward_func 一致）
- 推荐至少 **3 条/类** 训练数据，**1+ 条/类** 测试数据
- 数据越多 GRPO 训练效果越好

### Q: 能不能换任务（比如数字排序）？

**A**: 可以，改 3 处：
1. `data/make_data.py` —— 改 SYSTEM_PROMPT + 数据
2. `rl/reward.py` —— 改 `LABELS` 和提取逻辑
3. `eval/evaluate.py` —— 改 `LABELS`

## 训练类

### Q: SFT 训多少 epoch 好？

**A**: 取决于数据量：
- 8 条数据：**3 epoch**（再多就严重过拟合）
- 100 条数据：**1-2 epoch**
- 1000+ 条数据：**1 epoch**（数据够多不需要重复）

判断过拟合：看 `eval/evaluate.py` 在测试集上的准确率是否稳定。

### Q: GRPO 训练 reward 一直是 0？

**A**: 这是 GRPO 训练**最常见的失败模式**。原因：

1. **reward_func 拿不到 ground truth** —— 检查 dataset 有 `answer` 列，reward_func 签名包含 `answer` 参数
2. **completions 提取不到 label** —— 加 print 看 `completions[0]` 实际是什么（`list[dict]` 还是 `str`）
3. **SFT 模型过拟合到训练集** —— 4 次采样经常全对（reward=1.0 全 1.0）→ 组内无差异，advantage=0

**修法**：
- 减少 SFT epoch（让模型不过拟合）
- 增加 `num_generations`（G=4 → G=8）
- 增加训练数据量

### Q: `completions` 是 list[dict] 还是 str？

**A**: **trl 1.5.1 默认是 list[dict]**：`[{"role": "assistant", "content": "..."}]`

如果你的 prompt 是 messages 列表，trl 会推断 completions 也应该是 message 格式。

**修法**：在 reward_func 里解包：
```python
def _coerce_to_text(completion):
    if isinstance(completion, list) and completion:
        return completion[0].get("content", "")
    return str(completion)
```

### Q: `generation_batch_size must be divisible by num_generations` 错误？

**A**: 显式设 `generation_batch_size = per_device_train_batch_size * num_generations`：
```python
grpo_config = GRPOConfig(
    per_device_train_batch_size=1,
    num_generations=4,
    generation_batch_size=4,  # 1 * 4
    ...
)
```

### Q: `dataset_num_proc` 在 GRPOConfig 不存在？

**A**: `dataset_num_proc` 是 SFTTrainer 特有的，GRPOConfig 没有。**直接删掉**就行。

## 性能类

### Q: SFT/GRPO 训多少时间？

**A**: 经验值（Apple M5 Pro, 24GB 内存）：
| 阶段 | 时间 |
|---|---|
| SFT（8 条 × 3 epoch = 24 步） | ~30 秒 |
| GRPO（8 prompt × 20 step） | ~30 秒 |
| 评估（3 条测试集） | ~5 秒 |

**瓶颈**：每次生成都要从 CPU 搬数据到 MPS，4 个 completion 串行生成。

### Q: 推理速度多少 tokens/s？

**A**: 实测 49.15 tokens/s（200 tokens 长生成稳态）。

**为什么 SFT 训练 24 步才 27 秒？** 24 步 × (前向 + 反向) ≈ 1.1s/step，平均每秒训 ~0.9 步。

### Q: 能不能用更小的模型（< 0.5B）？

**A**: SmolLM2-135M 中文能力差，不推荐。Qwen2.5-0.5B 是 Qwen 家族**最小可训**的中文模型。

### Q: 能不能用更大的模型（1.5B+）？

**A**: 24GB 内存能跑 1.5B FP32，但训练激活会挤占：
- 1.5B FP32：~3GB 权重 + ~6GB 激活 = 9GB，**安全**
- 3B FP32：~6GB 权重 + ~12GB 激活 = 18GB，**勉强**
- 7B FP32：~14GB 权重 + ~30GB 激活 = 44GB，**OOM**

建议 1.5B 仍走 FP32；3B+ 试 BF16（但 MPS 有 bug 风险）。

## 评估类

### Q: 准确率怎么算？

**A**: 简单的正确数 / 总数。3 条测试集 → 准确率粒度 33%。

**改进**：
- 加测试数据（10+ 条更稳定）
- 加分类报告（precision/recall/F1 per class）—— 但 3 条数据样本太少，没意义

### Q: 为什么"颜色跟图片一样, 尺码标准"模型答"负面"？

**A**: 
1. 训练集"中性"样本只有 2 条（"物流一般, 3 天到的"、"产品能用, 没有特别的亮点"）
2. 模型严重过拟合，对"中性"边界理解不够
3. 这条测试样本本身**也有歧义**（"颜色跟图片一样" 也可以解读成"正面"）

**教学价值**：情感分类的"中性"边界本来就模糊，人工标注 5 个人可能 5 个答案。

### Q: 模型生成"正面\n请判断..."是什么回事？

**A**: SFT 模型**严重过拟合到训练集**，看到 prompt 后直接"背"训练集下一条数据。

**修法**：
- 训练更多数据（避免过拟合）
- 加 `<|im_end|>` 训练（让模型学会停）—— trl.SFTTrainer 默认会加，但模型可能没学
- 评估时限制 `max_new_tokens=5` 截断

## 概念类

### Q: GRPO 跟 PPO 有什么区别？

| 算法 | Critic 模型 | 优势估计 | 显存 |
|---|---|---|---|
| **PPO** | 需要单独训 | 单步 advantage | 2× 显存 |
| **GRPO** | 不需要 | **组内相对 advantage** | 1× 显存 |

GRPO **省一半显存**，因为不需要 Critic 模型。

### Q: 什么是 advantage？

A: `advantage = (reward - mean) / std`

- reward 高 → advantage 正 → 被强化
- reward 低 → advantage 负 → 被弱化
- 标准差 = 0（组内全对/全错）→ advantage = 0 → **没有信号**

### Q: KL 系数 (beta) 是什么？

A: GRPO loss 包含 **KL 散度惩罚**：
```
loss = -advantage × log_prob + beta × KL(policy || ref_model)
```

- beta=0：模型可能"学飞"（偏离 SFT 太远）
- beta=0.01：轻微约束（推荐）
- beta=0.1：强约束（模型几乎不动）

**ref_model** 在我们的实现里就是 SFT 模型本身。

### Q: 为什么用 SFT 模型作为 GRPO 起点？

A: 三个原因：
1. **冷启动** —— 原始 Qwen 不会分类，RL 训练信号全 0，没法学
2. **加速收敛** —— SFT 已经学会"任务"，RL 只学"优化"
3. **避免 reward hacking** —— 从 SFT 出发，模型已经有"正确的输出模式"，RL 只调整概率

工业界"先 SFT 后 RL"是**标准流水线**。
