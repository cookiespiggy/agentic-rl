## 13.1 RL 环境的核心接口

> **先说清楚：下面这个 `BaseEnvironment` 是概念示意，不是本仓库共用的基类。**
> 真实工程里，浏览器 / 代码沙箱 / 数据库三类环境的观测空间（页面文本 vs 源码 vs 表结构）和奖励结构差异很大，硬套一个接口往往得不偿失。本章 §13.2–§13.5 的三个环境类**都没有继承它**；后续 [16 - 网页导航 Agent 训练](./16-网页导航Agent训练.md)、[18 - 搜索增强 Agent 训练](./18-搜索增强Agent训练.md)、[19 - 垂直领域 Agent 训练](./19-垂直领域Agent训练.md) 也会按各自的场景定制接口。保留这段代码只有一个目的：把「环境 ≈ 一个带 `reset` / `step` 的交互循环」这件事讲清楚。

概念上的最小接口长这样（`step()` 的返回值统一用 gymnasium 的 5 元组）：

```python
from abc import ABC, abstractmethod

class BaseEnvironment(ABC):
    """RL 环境的概念示意（Base Class）"""
    
    @abstractmethod
    def reset(self) -> dict:
        """重置环境，返回初始观测"""
        pass
    
    @abstractmethod
    def step(self, action: str) -> tuple:
        """执行动作，返回 (obs, reward, terminated, truncated, info)"""
        pass
    
    @abstractmethod
    def get_observation(self) -> str:
        """获取当前观测"""
        pass
    
    @abstractmethod
    def compute_reward(self) -> float:
        """计算奖励"""
        pass
```

> **`step()` 返回值统一为 gymnasium 的 5 元组**：`(obs, reward, terminated, truncated, info)`。
> - `terminated`：任务本身结束（到达终态）；
> - `truncated`：被外部条件打断（超时、步数上限）；
> - `info`：字典，存调试信息。
>
> 只有 `terminated` 才算「这一条轨迹完成」。RL 训练里把这两个混为一谈，会让超时轨迹被当成正常终止，优势估计直接偏掉。本章后面所有 `env.step(...)` 都按这个约定解包。

## 13.2 代码执行环境（Code Sandbox）

### 13.2.1 简单的 Python 代码执行

```python
import os
import subprocess
import tempfile

class CodeSandbox:
    """安全的 Python 代码执行沙盒"""
    
    def __init__(self, timeout=10):
        self.timeout = timeout
    
    def execute(self, code: str) -> dict:
        """执行 Python 代码"""
        tmp = tempfile.NamedTemporaryFile(mode='w', suffix='.py', delete=False)
        try:
            tmp.write(code)
            tmp.flush()
            tmp.close()
            
            result = subprocess.run(
                ['python', tmp.name],
                capture_output=True,
                text=True,
                timeout=self.timeout
            )
            return {
                "stdout": result.stdout,
                "stderr": result.stderr,
                "return_code": result.returncode,
                "success": result.returncode == 0
            }
        except subprocess.TimeoutExpired:
            return {"stdout": "", "stderr": "Timeout", "success": False}
        finally:
            os.unlink(tmp.name)

sandbox = CodeSandbox()
result = sandbox.execute("print(2 + 3)")
print(result)
```

## 13.3 搜索环境（Search Environment）

```python
import requests

class SearchEnvironment:
    """搜索引擎交互环境"""
    
    def __init__(self, search_api_key, max_results=5):
        self.search_api_key = search_api_key
        self.max_results = max_results
        self.search_history = []
    
    def search(self, query: str) -> list:
        """执行搜索（以 SerpAPI 为例）"""
        response = requests.get(
            "https://serpapi.com/search",
            params={"q": query, "api_key": self.search_api_key, "num": self.max_results}
        )
        results = response.json().get("organic_results", [])
        self.search_history.append({"query": query, "results": results})
        return results
    
    def compute_reward(self, final_answer, ground_truth):
        """基于最终答案计算奖励"""
        if final_answer.strip() == ground_truth.strip():
            return 1.0
        return 0.0
```

## 13.4 网页浏览环境（Web Browser）

### 13.4.1 BrowserGym

```bash
pip install browsergym browsergym-miniwob
```

```python
import gymnasium as gym
import browsergym

from my_agent import MyAgent   # 你自己的 Agent：输入观测、返回动作字符串
agent = MyAgent()

# 创建浏览器环境
# 注意三点：任务 id 用连字符、任务目标参数叫 goal、页面文本在 page_content 键里
env = gym.make(
    "browsergym/miniwob/enter-text",
    task_kwargs={"goal": "Enter 'hello' in the text box"},
)

obs, info = env.reset()

# 观测里都有什么：
goal = obs["goal_object"]              # 任务目标（info 里没有 task 键）
page = obs["page_content"]             # 页面可访问性文本
elements = obs["interactive_elements"] # 可交互元素列表
bid = elements[0]["bid"]               # 元素句柄是 bid，不是 id

for step in range(10):
    # Agent 决定动作
    action = agent.decide(obs)
    
    # 执行动作（如点击、输入、滚动等）
    obs, reward, terminated, truncated, info = env.step(action)
    
    if terminated:
        break
```

> **BrowserGym / browsergym-miniwob 0.14.3 的几个坑**（写错了就是 `TypeError` 或 `KeyError`）：
>
> | 你可能写成 | 正确的是 | 说明 |
> |-----------|---------|------|
> | 环境 id 里用下划线 | `browsergym/miniwob/enter-text` | 任务 id 用**连字符**，下划线写法在 0.14.x 里不存在 |
> | `task_kwargs={"task": ...}` | `task_kwargs={"goal": ...}` | 任务目标参数叫 **`goal`** |
> | 页面文本取另一个键名 | `obs["page_content"]` | 页面文本只有 **`page_content`** 这一个键 |
> | `obs["elements"][i]["id"]` | `obs["interactive_elements"][i]["bid"]` | 元素句柄是 **`bid`**（bidirectional id） |
> | `info["task"]` | `obs["goal_object"]` | `info` 里**没有** task 键，任务目标从 **`obs["goal_object"]`** 取 |

> `bid` 是 BrowserGym 里唯一稳定的元素引用方式：DOM 每次 reset / 导航后都会变，只有 `bid` 在一次 episode 内有效，所以动作要写成 `click('bid12')` 这种形式。

## 13.5 数据库查询环境

```python
import sqlite3

class SQLEnvironment:
    """SQL 查询交互环境"""
    
    def __init__(self, db_path, schema_info):
        self.db_path = db_path
        self.conn = sqlite3.connect(db_path)
        self.schema_info = schema_info
    
    def __enter__(self):
        return self
    
    def __exit__(self, *args):
        self.close()
    
    def close(self):
        if self.conn:
            self.conn.close()
            self.conn = None
    
    def execute_sql(self, query: str) -> dict:
        """执行 SQL 查询"""
        try:
            cursor = self.conn.cursor()
            cursor.execute(query)
            if cursor.description:
                results = cursor.fetchall()
                columns = [desc[0] for desc in cursor.description]
                return {
                    "success": True,
                    "results": results,
                    "columns": columns,
                    "row_count": len(results)
                }
            self.conn.commit()
            return {"success": True, "results": [], "columns": [], "row_count": cursor.rowcount}
        except Exception as e:
            return {"success": False, "error": str(e)}
    
    def compute_reward(self, query, expected_result):
        """对比查询结果"""
        actual = self.execute_sql(query)
        if not actual["success"]:
            return 0.0
        if actual["results"] == expected_result:
            return 1.0
        if actual["columns"] and expected_result and "columns" in expected_result:
            if set(actual["columns"]) == set(expected_result["columns"]):
                return 0.5
        return 0.0
```

## 13.6 verl 中的环境配置

> **先纠正一个常见的错**：verl 里**没有**「从 `verl.tools` 导入一个工具注册器类」这条 API。`verl/tools/tool_registry.py` 只提供 `ToolType` / `initialize_tools_from_config` / `load_all_tools` 三个东西，照着旧教程写会直接 `ImportError`。
>
> verl 的真实机制是：**写一个 `BaseTool` 子类 → 在一份 YAML 里登记「类名 + 参数 schema」→ 训练时用 `multi_turn.*` 配置把这 YAML 指给 rollout。**

### 13.6.1 定义工具配置（YAML）

```yaml
# tools_config.yaml
tools:
  - class_name: "my_tools.PythonInterpreterTool"   # 你的 BaseTool 子类（含模块路径）
    config: {type: native}                          # native = 工具在本进程内执行
    tool_schema:                                    # 给模型看的函数 schema
      type: function
      function:
        name: python_interpreter                    # ← 工具名以这里为准
        description: "Execute Python code"
        parameters:
          type: object
          properties:
            code:
              type: string
              description: "Python code to execute"
          required: ["code"]

  - class_name: "my_tools.SearchTool"
    config: {type: native}
    tool_schema:
      type: function
      function:
        name: search
        description: "Search the web"
        parameters:
          type: object
          properties:
            query:
              type: string
              description: "Search query"
          required: ["query"]
```

### 13.6.2 实现工具类（`BaseTool` 子类）

```python
# my_tools.py
import json
import os

from verl.tools.base_tool import BaseTool   # verl v0.9.1 路径

from my_envs import CodeSandbox, SearchEnvironment   # 见 §13.2.1 / §13.3


class PythonInterpreterTool(BaseTool):
    """在子进程沙箱里执行 Python 代码。"""

    def __init__(self, config: dict, tool_schema: dict):
        super().__init__(config, tool_schema)

    async def execute(self, **kwargs) -> str:
        """真正干活的地方：参数由 tool_schema 的 parameters 决定。"""
        code = kwargs.get("code", "")
        sandbox = CodeSandbox(timeout=10)      # 见 §13.2.1
        result = sandbox.execute(code)
        return json.dumps(result, ensure_ascii=False)


class SearchTool(BaseTool):
    """搜索工具。"""

    def __init__(self, config: dict, tool_schema: dict):
        super().__init__(config, tool_schema)

    async def execute(self, **kwargs) -> str:
        query = kwargs.get("query", "")
        engine = SearchEnvironment(search_api_key=os.environ["SEARCH_API_KEY"])
        return json.dumps(engine.search(query), ensure_ascii=False)
```

> **名字必须对齐**：`BaseTool.__init__` 会从 `tool_schema["function"]["name"]` 取工具名。**YAML 里叫 `python_interpreter` 就全程叫 `python_interpreter`**——代码里不要再冒出第二个名字（写成 `code_interpreter` 的话，模型按 YAML 的 schema 发 `python_interpreter`，而你实现的是另一个名字，调用就对不上）。
>
> **import 路径**：`verl.tools.base_tool` 是 v0.9.1 的路径，不同版本略有差异，落地前用 `python -c "from verl.tools.base_tool import BaseTool; print(BaseTool)"` 确认一下。
>
> `execute()` 是 `async` 的——rollout 是并发跑的，同步阻塞的沙箱调用会把整个 rollout 拖慢，生产上要放进线程池 / 进程池。

### 13.6.3 把工具挂到训练上

```bash
python -m verl.trainer.main_ppo \
    actor_rollout_ref.rollout.multi_turn.enable=true \
    actor_rollout_ref.rollout.multi_turn.tool_config_path=tools_config.yaml \
    actor_rollout_ref.rollout.multi_turn.function_tool_path=my_tools.py \
    actor_rollout_ref.rollout.n=8 \
    actor_rollout_ref.actor.optim.lr=1e-6 \
    data.prompt_key=messages \
    data.train_batch_size=128
```

> 其余的键（模型路径、数据路径、batch 大小等）和第 15 章的训练脚本一样，照抄那一段即可；本章只强调工具相关的这三个 `multi_turn.*` 键。

> **三个 `multi_turn.*` 键各管什么**：
> - `multi_turn.enable=true`：打开多轮模式（模型可以连续调用工具，而不是一轮就结束）；
> - `multi_turn.tool_config_path`：指向 §13.6.1 那份 YAML——登记的是「你自己写的 `BaseTool` 子类」，verl 按 `class_name` 反射加载；
> - `multi_turn.function_tool_path`：指向一个 Python 文件，登记**函数式 / MCP 风格**的工具 schema。本章只演示 native 工具（`tool_config_path`）这一条路径。
>
> verl 的加载逻辑在 `verl/tools/tool_registry.py` 的 `initialize_tools_from_config` / `load_all_tools`。
>
> ⚠️ verl 里**没有** `tools.<name>.enabled` 这种配置段（网上很多旧教程是错的），多轮工具只有上面这三个键。

## 13.9 小结

- 环境是 Agentic RL 的核心组件，决定了 Agent 能学到什么
- 不同场景需要不同的环境：代码沙盒、搜索引擎、浏览器、数据库；**§13.1 的 `BaseEnvironment` 只是概念示意，各场景的接口按自己的观测与奖励结构定制**
- `step()` 统一用 gymnasium 的 5 元组 `(obs, reward, terminated, truncated, info)`
- verl 的工具注册 = **`BaseTool` 子类 + YAML（`class_name` / `config` / `tool_schema`）+ `multi_turn.*` 配置**，不是装饰器注册那一套
- BrowserGym 的三个易错点：env id 用连字符、任务参数叫 `goal`、观测键是 `page_content` / `goal_object` / `bid`
